## Recorded validation snapshot

The final September 15, 2026 `gpt-4o-mini` comparison contains **106 cases and 126 turns**. The separately recorded offline suite has **263 passing tests**.

| Mode | Adversarial PASS | WARN | FAIL | UNKNOWN | Benign utility PASS |
|---|---:|---:|---:|---:|---:|
| Unguarded | 29 | 8 | 6 | 0 | 9 / 10 |
| Guarded | 42 | 0 | 0 | 1 | 9 / 10 |

Each mode ran 43 adversarial cases and 10 benign probes. There were no runtime execution errors in this comparison. The guarded UNKNOWN records invalid judge output for `jb-01-ignore`; it is not counted as PASS. Both modes missed the customer reporting/dispute step in the fraud-protection utility rubric; the unguarded reply also disclosed restricted information. See the [validation record](validation.md) and [generated findings](findings_report.html) for the complete provenance and evidence.

These are results from one run under recorded settings. They do not establish complete attack coverage, production readiness, or general answer correctness. September 14 records remain historical evidence from an earlier runtime/evaluator and are not an equivalent baseline for the new scoring.

## How the documents fit together

1. **Source code defines implemented behavior.** The technical reference and architecture atlas explain that behavior and its design tradeoffs.
2. **Saved JSONL records define observed outcomes.** The findings reports are generated by `python -m redteam.report`; changing code or documentation does not retroactively improve old verdicts.
3. **The validation record separates offline regressions from live experiments.** Passing deterministic tests and observing model behavior are different kinds of evidence.
4. **The final paper integrates the maintained references.** It explains the project as a whole while retaining limitations and traceability to the code, tests, and results.

The six architecture diagrams cover system/trust boundaries, guarded versus unguarded requests, account and policy access, four-turn risk recovery, schema-v2 evaluation, and the SQLite data model. The visual atlas retains an explicitly labeled training-reference section containing fictional fixtures and baseline attack objectives.

## Scope to retain when reusing these materials

- Name-only sign-in is a demo identity selector. The guarded tool enforces the supplied session ID; it does not establish the person's identity.
- Account and policy tools retrieve data. They do not move money, freeze cards, create disputes, or execute the operations described in fictional policy prose.
- A review action returns a static message. No human-review queue or external handoff is integrated.
- Input/output patterns, canary detection, and utility rubrics have bounded coverage. The optional input classifier allows continuation on failure, and the report preserves incomplete judging separately from PASS.
- Configured credentials are not added to evidence, but prompts and tool results are recorded. Review captured content before sharing exported artifacts.
